# 01 · Struct Skeleton (Python)

Python port of `week1_baseline/ruby/01_struct_skeleton`.

> Requires the shared environment. If you haven't run `uv sync` in `week1_baseline/python`, do
> that first — see [`../README.md`](../README.md).

This step defines the data structures every later step passes around. It is deliberately inert:
construction and display only, no behaviour beyond that.

## Data structures

### `Tool`

| Field | Description |
|---|---|
| `name` | The name of the tool |
| `description` | Shown to the agent so it knows when to invoke the tool |
| `parameters` | The arguments that need to be passed in, as `name → {type, description}` |
| `block` | The callable that runs when the tool is invoked |

```
#<Tool name=move description=Move the player in a direction (north, so params=[:direction]>
```

### `Message`

A single unit of conversation.

| Field | Description |
|---|---|
| `role` | Who is speaking — `user`, `assistant`, or `tool_result` |
| `content` | The text generated by the agent or provided by the user |
| `tool_use_id` | Links a tool result back to the call that requested it. The API requires this pairing to be exact. Omitted from output when absent. |

```
#<Message role=user content=Explore north and tell me what you find....>
#<Message role=tool_result [toolu_01X] content=You move north into a torch-lit corridor....>
```

### `Context`

Holds everything Boukensha needs to make an API call. Nothing lives outside of this.

| Field | Description |
|---|---|
| `task` | The task **class** (e.g. `Player`), not an instance |
| `system` | Tells the agent what its job is. Sent as a separate API field, never inside `messages`. |
| `messages` | The full conversation history, replayed on every turn |
| `tools` | The registered tools the agent may invoke, keyed by name |

```
#<Context task=player turns=2 tools=1>
```

## Differences from the Ruby original

| Ruby | Python | Why |
|------|--------|-----|
| `Struct.new(...)` | `@dataclass` | Positional construction, mutable fields, value equality. Not `NamedTuple` — later steps mutate these. |
| `str[0..40]` / `str[0..60]` | `str[:41]` / `str[:61]` | Ruby ranges are **inclusive**. A naive `[:40]` silently drops one character. |
| `parameters.keys` → `[:direction]` | `ruby_symbol_list(...)` | Ruby prints symbol arrays as `[:direction]`; Python would print `['direction']`. |
| `nil.to_s` → `""` | explicit `None` guards | `None` must never reach an f-string. |
| `def tool_count = @tools.size` | `@property` | Ruby endless method, called without parens. Keeps call sites identical. |
| `initialize(task:, system: nil)` | `def __init__(self, *, task, system=None)` | `task` is a **required keyword** in Ruby; positional construction must fail. |
| `:user` symbol role | `"user"` string | Output is identical; no symbol emulation needed here. |

## A note on `system`

`Context.system` resolves to `None` in this step — in **both** trees. Step 01 drops the
`PROMPTS_DIR` constant and ships no `prompts/` directory, so `system_prompt` consults only the
user override dir, and no `.boukensha/prompts/player/system.md` exists. This is faithful to the
Ruby original, not a port bug. Prompt plumbing returns in a later step.
